**Palinopsia v1.2.1 : reading the picture back for free.**

A maintenance release about one thing : the instrument reads its own composed picture back
every frame, to turn it into the 17 vision features, the Sonify taps and the depth
estimator's input, and on a computer whose graphics chip shares memory with the processor
that read stopped the instrument dead for about 17 ms each time. Opening the Performance
tab turned it on, so the show spent half of every second waiting inside the graphics
driver, and nothing in the app showed it, because the stall happens below the app. The
reads are now queued and collected a frame or two later, and the picture never waits. On
an 8 GB Apple-silicon Mac Mini that took a blank 1080p session with the Performance tab
open from 41.9 to 50 fps, up to a steady 50 of 50. The picture itself is untouched : the
same passes, the same formats, the same resolution.

The release also fixes the readouts that made the frame rate hard to read in the first
place. The frame rate is now shown against the refresh rate of the display the window is
on, because the render is locked to it and that rate is the ceiling, not 60.

## Highlights

- **The picture readout is free now.** The vision features, the Sonify taps and the depth
  frame are collected through a ring of buffers with fences instead of a blocking read.
  Measured on an 8 GB Apple-silicon Mac Mini, blank 1920x1080 session, 50 Hz display,
  Performance tab open, three runs each : **41.9 to 50.0 fps before, 50.0 fps every time
  after.** The app's own meter reads **1.4 ms of processor time per frame instead of
  14.2**, the vision return **1.0 ms instead of 13.5**, and the worst single frame
  **5.5 ms instead of 42.8**. Blocking readback time fell from **560 ms per second to
  0.1**.
- **The frame rate reads against the display.** `50 fps / 50 Hz` in the Performance tab
  and in the corner of the preview. Matching the refresh rate means every frame is being
  drawn : 24 fps on a display set to 24 Hz is not a dropped frame. The red warning is now
  85% of the refresh rate, and the frame-budget figures use one frame on that display
  (20.0 ms at 50 Hz) instead of a fixed 16.7.
- **Dropped frames are visible.** The frame rate counts frames that were drawn. The GPU
  backlog guard skips a frame when the graphics card is two frames behind, and those
  returned before the counter ran, so a guard throttling the render looked exactly like a
  slow display. A `skips` reading now sits beside the frame rate.
- **The GPU and VRAM meters work on a Mac.** They used to read "-" there for the whole
  session, because they asked a discrete-card tool that does not exist. Where the graphics
  chip shares system memory they now read the statistics the operating system already
  publishes : utilization, and the driver's share of total memory.
- **Screen capture explains itself on a Mac.** Reading the screen needs a permission you
  grant by hand, and no app may ask for it. Without it the picker used to fill with black
  rectangles and nameless windows, with nothing to say why. It now asks the system first,
  opens the right settings pane on a click, and tells you the part that is easy to miss :
  the permission is read when the app launches, so it takes effect the next time you
  start Palinopsia, not straight away. Cameras and video files were never affected.

## Install

| Platform | File |
|---|---|
| **Windows** | `Palinopsia-1.2.1-win-x64.exe` (installer) or `Palinopsia-1.2.1-portable.exe` |
| **macOS** (Apple Silicon) | `Palinopsia-1.2.1-mac-arm64.dmg` |
| **Linux** | `Palinopsia-1.2.1-linux-x86_64.AppImage` or `Palinopsia-1.2.1-linux-amd64.deb` |

Builds are unsigned :
- **Windows** : SmartScreen may warn, click **More info → Run anyway**.
- **macOS** (Apple Silicon) : not notarized. Drag Palinopsia into **Applications** first
  (run from the disk image or Downloads, macOS runs a hidden temporary copy), then run
  `xattr -cr /Applications/Palinopsia.app` once in Terminal, or open it and click **Open
  Anyway** in System Settings → Privacy & Security. The first launch asks for the local
  network, and for the camera and the microphone when you use them : accept, or OSC, NDI
  and light output stay silent.
- **Linux** : `chmod +x` the AppImage, then run it.

Sessions saved with v1.2.0 open unchanged, and nothing in this release alters the picture.

**Intel Macs (x64)** : this release ships Apple Silicon only. On an Intel Mac, build from
source (`npm install`, then `npm run build:mac`).

## For developers

- `src/renderer/src/engine/gridReadback.ts` is the small-grid counterpart to
  `frameCapture.ts` : pixel-pack buffers, `fenceSync` plus a zero-timeout
  `clientWaitSync`, newest finished grid wins and older finished ones are dropped unread,
  and `kick()` skips rather than waits when every slot is still in flight. A `gl.flush()`
  follows the fence, because a window that is not painting never flushes on its own and
  the read would otherwise only start when something came to collect it.
- The one synchronous read left is the single pixel in `finishFrame()`, which is
  deliberate backpressure and only runs on the timer clock.
- `PerfStats` carries `hz`, the refresh rate of the display the main window is on, so it
  rides the resource sample that was already being polled. A separate `display:hz` channel
  returns just that rate, for readouts that want the ceiling without paying for a sample.
- The cost of a synchronous readback on a shared-memory GPU is the pipeline drain, not the
  bytes : 1x1, 32x32 and 256x256 all measured the same. Size is not the knob.
